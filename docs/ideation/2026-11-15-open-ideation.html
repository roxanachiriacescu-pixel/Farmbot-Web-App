Grounding context

Codebase context

FarmBot Web App is a Rails JSON API + React 19/TypeScript frontend + MQTT realtime path for CNC-style garden robots. The product is hosted-first at my.farm.bot; self-host is supported but warned as expert-only. The frontend still uses classic Redux consumers, BlueprintJS, i18next, and a large command palette. Garden editing now has two surfaces: the long-standing 2D farm_designer map and a production 3D garden (@react-three/fiber) after three_d_garden defaulted to true.

Recent momentum: 3D out of beta, scene objects, area selection, a large 3D performance hill-climb journal, command-palette fixes, GCS image uploads, and sequence unpublish work. Open issue themes that still bite: timezone/date (#2388), Message Center v2 (#1897), Help Modals (#1766), motor stall UX (#2391), sequence variable rename (#2416), self-host CSP (#2505), weather-aware watering (#2498).

No STRATEGY.md / CONCEPTS.md / docs/solutions/ yet. The densest institutional corpus is docs/three_d_garden_performance_hill_climb.md (acceptance bar: ≥10% plus meaningful absolute savings at realistic N, no UX quality cuts).

External context

Adjacent 2025–2026 signals: irrigation products that explain skips (Rachio / Home Assistant), robotics ops layouts (Foxglove), local-first ag twins, and consumer garden robots that lead on offline and exception UX. Forum and research pressure around offline Lua/API coupling, self-host migration, and richer sequence debugging.

1

Exception Ops Console

Confidence 68% Complexity High

Reboot Message Center from dismissible setup cards into a garden exception console: stalls, rain holds, offline windows, and quota pressure as actionable strips that clear when resolved. Pair with 3D stall forensics (#2391, now unblocked by 3D GA) and audited weather go/no-go for watering (#2498), feeding the same digest/ops surface.

Basis

direct: #1897 Message Center v2; MESSAGES_PANEL still describes “setup cards and announcements… Check back often”; #2391 deferred trail/heatmap work until 3D production (now true); #2498 weather watering ask. external: Rachio/HA irrigation exception UX; ATC-style flight strips / Agtonomy exception queues.

Rationale

Announcement UX and ops UX optimize opposite metrics. Turning the center into cleared exceptions changes what “done” means for years-old issues and uses 3D where it earns trust.

Downsides

Large product reframe; weather data provenance and auto-skip liability; must not bury remaining setup cards. Verifier noted the ATC/black-box stack is aspirational — ship as a sequenced program, not one PR.
2

Garden Clock Contract

Confidence 72% Complexity High

Declare one garden clock: authoring for plants, farm events, regimens, and digests happens in bot-local civil time; UTC is computed only at the MQTT/device edge. Surface a persistent bot-vs-browser clock indicator when they diverge. Kill the class of off-by-one date bugs (#2388) with a contract, not another widget patch.

Basis

direct: #2388; plant status edits convert date strings through utcOffset; FarmEvents::CleanExpired and digests already depend on device.timezone; Content.DIFFERENT_TZ_WARNING / TzWarning admit the split. external: observatory site-time vs absolute-time scheduling analogy.

Rationale

Timezone defects silently mis-time irrigation and planting age. A single contract removes the conversion surface that regenerates the bug class.

Downsides

Touches many consumers; FBOS and browser edges must agree; migration of stored UTC values is careful work. Not a thin fix — schedule as a domain project.
3

Single Spatial Truth

Confidence 70% Complexity High

Make the production 3D garden the write path for garden state. Demote interactive 2D to a derived orthographic/export/accessibility projection. Elevate scene objects into the shared spatial graph both views read, so area selection, stalls, and fixtures stop shipping twice.

Basis

direct: migration 20260728183708_change_three_d_garden_default sets three_d_garden default true; dual stacks remain in farm_designer/map and three_d_garden; scene objects already quota-capped (MAX_SCENE_OBJECT_COUNT = 1000) and rendered in 3D. reasoned: parity debt is a product choice, not physics.

Rationale

Every new spatial capability currently pays a double tax. One truth surface compounds the 3D investment already made.

Downsides

Major rewrite; accessibility and low-power users still need a 2D path; risk of alienating muscle-memory 2D power users if projection is underpowered.
4

AI Ops Co-pilot

Confidence 84% Complexity Medium

Broaden AisController from sequence title/color/description (and separate Lua codegen) into a farm-ops context bus: propose interventions — safe variable rename sets, stall explanations, rain-hold suggestions — that humans approve. Sequences become one output format, not the only AI job.

Basis

direct: sequence_inner_prompts only covers description/color/title while Lua is a separate full-codegen path; throttle policy already exists. grounded pains #2416 / #2391 / #2498 benefit from structured proposals rather than metadata autocomplete.

Rationale

AI spend and throttle budget already exist; widening context multiplies value across editor, ops, and watering without a second AI stack.

Downsides

Prompt/safety review; must not invent garden state; hosted vs self-host AI availability becomes a sharper product fork.
5

Sequence Variable Rename Pass

Confidence 88% Complexity Low–Medium

When a local variable is in use, stop blocking rename. Perform an atomic CeleryScript identifier rewrite across the body (with collision warnings and preview), treating sequences as a language with a compiler pass rather than a form.

Basis

direct: #2416; variable_form.tsx uses a read-only label and error(t("Can't edit variable name while in use.")) when inUse — rename is blocked exactly when it matters most.

Rationale

Highest confidence / lowest burden survivor. Unlocks safer AI-authored sequences and removes a footgun power users hit on complex graphs.

Downsides

Lua string references may be incomplete; need undo/preview; collision with identically named identifiers across scopes.
6

Palette Capability Registry

Confidence 65% Complexity Medium

Promote the command palette from a flat searchable list into the capability registry every feature publishes into (structured intent + params). AI tool-calling, Help Modals, hotkeys, and future HA/MQTT remotes then share one surface. Add mission layouts (“debug stall”, “author watering”) that rearrange panels like Foxglove presets.

Basis

direct: frontend/command_palette/commands.tsx already spans panels, device actions, sequences, regimens, crops, scene objects, settings. external: Foxglove saved layouts. reasoned: without a registry, each channel grows a parallel entry-point map.

Rationale

Amortizes discoverability and integration work. Makes “ships a palette capability” a definition of done that compounds.

Downsides

Verifier correctly notes today’s list is not yet a registry — this is a disciplined refactor, not a rename. Migration tax across ~thousands of lines of commands.
7

Hill-climb Ritual Export

Confidence 86% Complexity Low

Extract the 3D hill-climb acceptance rule into a reusable engineering ritual for any expensive surface (2D map, MQTT reconnect, digests, sequence viz): realistic N, ≥10% plus meaningful absolute gain, no UX quality regressions, rollback on collateral damage. Seed docs/solutions/ so future agents stop rediscovering folklore from a 19k-line journal.

Basis

direct: docs/three_d_garden_performance_hill_climb.md already encodes the bar and hundreds of accept/reject decisions; learnings search found docs/solutions/ missing — institutional knowledge is centralized nowhere else.

Rationale

Highest leverage documentation move in this run: turns a one-off 3D diary into Compound Engineering memory for the whole repo.

Downsides

Ritual without enforcement becomes shelfware; needs a short checklist owners actually cite in PRs.
